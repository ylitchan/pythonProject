# 币安 OI 与多空比接口只返回已走完的周期，时间戳是收盘时刻

## 背景

把 AUTOBN BZ 做多路径从 1h 换成 1d 时，我在 ff-note 里写了条顺手发现，说 `_get_oi_1d_data` 的可得边界 `timestamp <= 当天UTC零点` 会含进「当天那根未走完的日线」。这是拿 K 线的直觉套到了统计类接口上，判断错了。

## 结论

**`openInterestHist`（OI 历史）和 `longShortAccountRatio`（多空人数比）跟 K 线不是一回事：**

1. **不存在进行中的当期数据**。不管 period 传 5m / 1h / 1d，返回的每一根都是已经走完的周期。K 线（`kline_candlestick_data`）会返回进行中的当期，这两个接口不会。
2. **时间戳是周期的收盘时刻**，等于下一个周期的起点。所以 1d 的末根时间戳就是**今天的 UTC 零点**（那根装的是昨天一整天），1h 的末根时间戳就是当前整点，5m 同理。

由此推出两条工程结论：

- **`timestamp <= 当前周期边界` 这个过滤是有效的边界判断，不是空操作**。末根正好落在边界上被保留，超出边界的（异常数据）被丢掉。别因为「没有未走完的数据」就把它当冗余删掉。
- **「末根 == 当前周期边界」是判断「还要不要再拉一次」的正确判据**。跨过边界后币安发布新一根有延迟，这段窗口里拉到的末根还停在上一个边界，所以「对上边界」意味着「已经是此刻能拿到的最新，不用再打 API」，「对不上」意味着「可能还有更新的，值得再拉」。

  这里有过一次口径反复，值得记住结论：这个判据**不适合用来否决数据**。1h 时代和 2026-07-28 的第一版 1d 修复都是「不对齐就不写缓存 + 返回空让上层条件不成立」，即失败关闭；但发布空窗期本身是常态而不是异常，把它当异常处理等于在每个周期开头制造一段策略盲区。最终口径改成**末根时间戳单调推进**：对不上就拉，拉回来比末根，严格更新的才替换缓存，取用一律读缓存。判据只决定要不要打 API，不决定数据能不能用。详见 `.codestable/issues/2026-07-28-5m-cache-ttl-stale-window/5m-cache-ttl-stale-window-fix-note.md`。

- 与代码互证：`_is_current_5m_bar` 判 5m、`_bar_timestamp_ms(...) == _utc_day_start_ms(dtn)` 判 1d——只有「时间戳是收盘时刻」才能让刚发布的那根正好等于当前周期边界。（这两处的前身是按年龄判新鲜度的写法，同样只在「时间戳是收盘时刻」下成立。）
