# 币安 OI 与多空比接口只返回已走完的周期，时间戳是收盘时刻

## 背景

把 AUTOBN BZ 做多路径从 1h 换成 1d 时，我在 ff-note 里写了条顺手发现，说 `_get_oi_1d_data` 的可得边界 `timestamp <= 当天UTC零点` 会含进「当天那根未走完的日线」。这是拿 K 线的直觉套到了统计类接口上，判断错了。

## 结论

**`openInterestHist`（OI 历史）和 `longShortAccountRatio`（多空人数比）跟 K 线不是一回事：**

1. **不存在进行中的当期数据**。不管 period 传 5m / 1h / 1d，返回的每一根都是已经走完的周期。K 线（`kline_candlestick_data`）会返回进行中的当期，这两个接口不会。
2. **时间戳是周期的收盘时刻**，等于下一个周期的起点。所以 1d 的末根时间戳就是**今天的 UTC 零点**（那根装的是昨天一整天），1h 的末根时间戳就是当前整点，5m 同理。

由此推出两条工程结论：

- **`timestamp <= 当前周期边界` 这个过滤是有效的边界判断，不是空操作**。末根正好落在边界上被保留，超出边界的（异常数据）被丢掉。别因为「没有未走完的数据」就把它当冗余删掉。
- **判断数据够不够新，要断言「末根 == 当前周期边界」**。跨过边界后币安发布新一根有延迟，这段窗口里拉到的末根还停在上一个边界。1h 时代的写法是 `if oi_1h[-1]["timestamp"] == 当前整点: 才写缓存`，正是为了防这个：不对齐就用但不锁进缓存，下次调用重试。周期越长这个漏洞越贵——1d 缓存按 UTC 日键控，一旦在零点后的发布空窗期写进去，整整一天都拿不到昨天那根。

## 证据

- 用户口头确认（2026-07-28）：「oi和多空比，不管是啥周期的，bn都只能看到前一个周期，这些数据和k线不一样，不存在没走完的数据」「bn数据的末根的时间戳就是今天的零点」。
- 与代码互证：`_get_bd_oi_windows` 用 `dtn.timestamp() - ts/1000 <= 300` 判 5m 新鲜度、`_get_lsr_5m_data` 同样口径——只有「时间戳是收盘时刻」才能让刚发布的那根算出个小的正值年龄。
