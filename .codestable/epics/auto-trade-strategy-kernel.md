# 单文件自动交易策略基类重构

起点：`tokenDemo/autoTrade_pm.py` 中 AUTOA 与 AUTOBN 位于同一策略层，但 AUTOA 使用类级状态、AUTOBN 使用实例状态；状态落盘、HTTP 会话、通知、行情获取、标的池刷新、信号判断和调度入口存在重复或不对称实现。

目标：一个可直接运行的单文件 `tokenDemo/autoTrade_pm_refactored.py`，由交易引擎承载稳定的生命周期和公共运行能力，由 AUTOA/AUTOBN 策略实现市场差异；行情源、执行器与业务状态各自拥有唯一责任，旧文件保留为行为基线。

范围：

- 两个策略统一为实例对象，消除类级可变运行状态。
- 抽象状态加载/保存/退出注册、HTTP 会话、公共通知路由、概率计算和运行期缓存容器。
- 第一阶段曾抽象 `refresh_universe()`、`fetch_bars()`、`evaluate_signal()`、`manage_position()`、`execute_action()`；第二阶段由 `TradingEngine`、`MarketStrategy`、`MarketData`、`TradeExecutor` 和 `TradingState` 形成唯一责任链。
- AUTOBN 每日账户推送后刷新一次交易对元数据；AUTOA 收盘后每日推送后刷新一次涨停池。
- AUTOA 涨停池刷新采用“新增或刷新”语义，不删除未命中的旧观察记录；失败或空结果视为无变化。
- 保留两种 ATR 算法、通知时序、真实/虚拟交易差异、现有状态 JSON 结构和业务策略规则。
- 用户补充：账户专用于策略，取消原每 15 分钟全量持仓同步；启动和每日刷新标的池仍读取实际持仓并核对已登记状态，交易前按需核对实际仓位。缺少策略记录的实际仓位按DEC-23恢复为N管理，不能当作空仓下单。
- 2026-09-09 用户授权试用同花顺免费统一A股数据源，取代原三源方案；具体来源与数据口径例外见 DEC-20。新运行入口不需要 AkShare。

非目标：

- 不修改原 `tokenDemo/autoTrade_pm.py` 的行为基线。
- 不合并真实不同的指标算法或策略规则；行情源原始响应只在边界转换，策略统一消费 `MarketBars`。
- 不改变 BZ/BD/N、OI、多空比、基差率、止盈止损和 DCA 规则。
- 不把持久化业务状态与运行期缓存混为一体。

## 关键决策

- **DEC-1 · 单文件入口**：所有重构后的基类、子类、数据契约和调度代码保留在新增单文件中，用户以后运行该文件。
- **DEC-2 · 实例生命周期**：基类和两个子类均使用实例状态；类属性只保留不可变常量，不保存可变缓存、HTTP session 或交易状态。
- **DEC-3 · 市场扩展接口**：第二阶段策略只实现标的池刷新、行情规则、信号/持仓决策、状态变更和每日报告数据；引擎统一顺序，行情源统一数据边界，执行器统一真实/虚拟动作。
- **DEC-4 · 标的池刷新**：AUTOBN 在每日账户推送后刷新交易对元数据；AUTOA 在收盘后推送完成后刷新涨停池。AUTOA 只新增/刷新观察记录，不删除未命中记录。
- **DEC-5 · 缓存归属**：缓存集中在每个策略实例的运行期缓存容器中；市场专属缓存由子类扩展，禁止使用共享可变类属性。
- **DEC-6 · 兼容基线**：新文件完成前保留旧入口；以旧文件的状态、信号、持仓、通知和指标结果作为对照基线。
- **DEC-7 · 每日统一时序**：引擎 `push_daily_report()` 必须按 `build_daily_report()` → PushPlus → `refresh_universe()` → `save()` 执行。报告构建或通知失败仍尝试刷新，刷新失败仍保存已完成状态；取消任务要传播取消，保存异常不能吞掉取消。完整持仓/观察快照仅在每日流程和退出时保存；真实订单的增量恢复日志按 DEC-16 处理。
- **DEC-8 · 调度与启动**：AUTOBN 每日 08:00、AUTOA 每日 15:06（Asia/Shanghai）。AUTOA 先确认实际交易日，非交易日全流程短路；盘中监控不再获取涨停池，15:00 后不执行盘中交易。币安无快照时启动补拉一次，失败后等待每日刷新，不由分钟任务无限重试。AUTOA 启动复用持久化观察，空池等待当日收盘，不用盘中未完成涨停池冒充收盘池。
- **DEC-9 · 观察池合并**：新标的以收盘价、刷新时刻和空策略加入；命中旧标的刷新时间戳，已有 BZ 时按原 `_update_bz_observation` 更新最低价/基准，保留冷却字段；未命中旧标的不删除。顶层接口失败或空池不修改观察，单标的行情失败跳过该标的。既有无 BZ 观察不因改造额外补 BZ。
- **DEC-10 · 并发边界**：每日任务和分钟扫描共用实例级锁，批次串行、批次内行情有界并发；待确认冷却共用一次日历请求且不占行情槽位。退出先停止调度并等待任务收尾，再关闭连接和刷记录；退出阶段的完整快照仅由 atexit 回调保存，不在 main 再存一次。
- **DEC-11 · 日报查询集合**：币安日报只对本地登记且仍存在于账户查询结果的持仓估值；报告构建不修改 `POSITIONS`；未登记实际仓位由随后刷新与扫描按DEC-23恢复管理。余额仍读取实际账户余额。
- **DEC-12 · 元数据应用**：币安每次正式刷新直接执行一次交易所元数据请求，完整解析后同步替换交易对/精度缓存，成功后使下一批重新构建快照；异常、空数据或没有合格交易对保留旧快照。运行中的每日入口由调度器每天触发一次，每次调用日报均执行刷新，不额外增加“同日禁止再次调用”的门槛。
- **DEC-13 · 等待和时间**：日报构建/标的刷新分别有上限，通知等待使用公共 HTTP 超时；超时后锁能释放，后续阶段按 DEC-7 执行。业务时钟与上海调度时区一致，日历按上海日期比较，重开午夜时间戳不依赖宿主时区。
- **DEC-14 · 缺失精度**：启动元数据补拉失败时不由扫描循环重新拉全池；全平复用交易所确认的实际持仓数量，部分平仓没有精度时明确延后，不猜测数量、不发送订单或推进止盈状态。后续每日刷新成功后恢复有精度的部分平仓。
- **DEC-15 · 多仓止盈后价格保底（2026-09-09 用户追加）**：此项是对上文“止损规则不变”的明确例外。AUTOBN 多仓开仓时以下轨写入 `stop_loss`；此值不随止盈或 DCA 重算，仅 `tp_count > 0`（已成功止盈）后在现价等于/低于该正数下轨时全平，记为“止盈后价格止损”，并先于 DCA 和 OI 请求执行。OI 止损仍在所有阶段有效；空仓/AUTOA不变。失败止盈不增加计数，不启用保护；重启使用已保存计数和阈值。旧持仓不回填无法还原的初始下轨，沿用已有 `stop_loss`。
- **DEC-16 · 外部副作用待确认（2026-09-09 第二阶段，修复补全）**：真实订单提交开始后，取消/执行结果未知不能当作拒单重提；执行器必须以 client order id 补查。明确的参数、权限、余额/保证金拒绝终结动作，不冻结已有持仓；未知结果保留 `PENDING_ORDERS`，下一轮只补查。`TradingState` 在 `状态文件.orders.jsonl` 追加 pending/resolved 事件，已确认状态仅按标的记入增量日志，不逐笔重写完整快照。启动重放快照之后的日志，完整快照带 `ORDER_JOURNAL_SEQUENCE` 检查点，保存后清理已覆盖日志；中断的尾行不妨碍恢复。确认成交后的补查取消仍提交已确定状态再传播。AUTOA 虚拟动作不建立订单日志或逐笔持久化；旧快照遗留的虚拟 pending 取消后按最新行情重评。
- **DEC-17 · 启动/每日持仓核对与下单前置（2026-09-09 用户纠正）**：启动补拉及每日标的池刷新均读取实际账户持仓，不恢复每 15 分钟同步。日报与随后同轮刷新复用账户响应。已登记仓位保留止盈计数、策略、止盈价和固定初始下轨，仅校正实际均价、移除已确认不存在的仓位；未登记实际仓位进入DEC-23的N恢复队列，不伪造原始信号。OPEN 要求账户该标的确实空仓，ADD 要求对应方向仍有实际仓位；否则拦截首次开仓或取消加仓并清理旧记录。格式不完整的账户响应不能视为空仓。
- **DEC-18 · A股历史行情失败与扫描结果（2026-09-09 修复）**：历史日线优先东方财富前复权，接口异常/空数据时在同一 `AshareMarketData` 内使用腾讯 `qfqday`，字段顺序在数据源边界转换、成交量仍以手表示，仅缓存请求日期范围内的已完成日线，再拼接新浪实时日线。不使用未复权数据顶替前复权，不绕过无日历时的当日交易确认；两源失败则跳过并说明原因。扫描分别统计正常处理、规则跳过、无行情、待确认和异常。失败加仓/平仓及确认零仓继续原有观察后处理，未知真实订单和失败首次开仓仍终止本轮。
- **DEC-19 · 审查补全的故障边界**：订单日志写入/flush/fsync 报错后回滚到原有效长度，未提交 pending 不得在下次启动被重放；已确认成交在引擎按客户端订单 ID 防止重复应用，日志终态重试不重复记账，Excel 增加可选“订单编号”对同一真实成交跨重启去重，历史无编号记录原样保留。交易对元数据和实际持仓读取独立成败，已取得有效账户响应即应用核对；无有效响应保留本地状态。东方财富非空但缺字段/无有效行情数值也触发前复权备用源。
- **DEC-20 · 同花顺免费统一源试用（2026-09-09 用户授权）**：此项取代 DEC-18/19 的A股多源取数部分。`AshareMarketData` 通过现有 aiohttp 直连同花顺公开端点，历史前复权日线 `/v6/line/hs_{code}/01/last.js`，当日日线同路径 `today.js`，涨停池 `/dataapi/limit_up/limit_up_pool`，交易日历 `/dataapi/limit_up/trade_day`；不引入收费账号/SDK，不回退新浪/腾讯/东方财富。来源的完整日内高低价、长历史复权值可能与旧输入不同，owner已知情授权试用；指标算法、信号、DCA、开平仓数量规则不改。
- **DEC-21 · 统一源数据边界**：历史及当日成交量均由股转手；历史按原请求日期范围切片，仅缓存已完成日线，然后拼接带明确日期的当日OHLCV，不重复当日线。实时数据要求日期对应本轮、OHLCV有限有效、有当日成交，时间落后当前连续交易结束点不超过5分钟（午休按11:30，收盘按15:00）；旧日/过期/畸形数据跳过并记录原因。日历失败时只有当日日线明确证明交易日期与成交量才能执行原 exit_only 路径，仍禁止新开仓/DCA。HTTP/超时/JSON或JSONP语法解析异常最多重试1次，取消传播；业务字段/schema缺失直接按失败跳过、不应用部分结果；JSONP只解析JSON不执行脚本。涨停池完整分页、总数核对，缺页/重复/变化/失败不应用部分池，空池不清已有观察；日历仅在两侧各至少60条合法交易日完整返回后缓存，覆盖当前锚定日期前后各60交易日，不能把缓存范围外日期推定为交易日，旧平仓冷却必要时按原日期重新获取。
- **DEC-22 · 依赖边界**：新入口不导入AkShare或其JS解码运行时，A股只依赖既有aiohttp/pandas/标准库；仓库仍使用AkShare的旧脚本由可选依赖 `legacy-market-data` 支持，`uv run --extra legacy-market-data ...` 运行它们，默认依赖移除AkShare。pyproject与uv.lock同步，包锁定版本不升级，旧源码保持。

- **DEC-23 · 断电与遗留持仓风控恢复（2026-09-10 用户纠正）**：真实账户专用于策略，JSON缺记录不能导致实际仓位无人管理。先由现有订单日志恢复原状态；仍缺记录的账户仓位在启动/每日核对标记为待恢复，扫描复查实际方向/均价与K线后建立N恢复持仓，原始策略/DCA/止盈次数无法还原时不伪造（计数0、日期为恢复日期、价格轨道使用当前ATR）。多仓缺失/无效guard及N恢复共用原阈值公式：min(max(最近30小时OI、最新5分钟OI)*0.9，前述小时样本剔除末6根后的均值+10倍样本标准差)。正常开仓已要求当前OI>=小时峰值，复用公式保持原行为；有效正有限guard不重算。恢复时当前OI<=阈值当轮全平，否则才允许后续DCA；取数/阈值无效不DCA，不伪造零保护的恢复仓位，已有止盈/价格退出仍优先。实际零仓及恢复成功清除待恢复候选，恢复失败继续重试；双向同币仓位超出现有单币单仓模型时明确报错。恢复所得是当前风控基准，不是历史峰值或原始开仓阈值；状态仅由引擎应用patch，完整快照与订单日志保存时序不变。

## 扩展接口契约

2026-09-09 第二阶段：用户接受进一步统一业务抽象，以下新契约替代第一阶段“子类自行执行并提交状态”的结构约束，仍保持单文件。历史阶段验收结果保留。

- `TradingEngine` 唯一拥有扫描/日报、决策应用、交易阶段、记录和通知顺序；`MarketStrategy` 只处理规则，AUTOA/AUTOBN 是同层实例子类，不再继承保存/HTTP/下单等基础设施。
- `MarketBars` 用带字段名的 OHLCV 序列与时间统一行情；Binance/A 股数据源分别解析响应、维护缓存并提供市场扩展数据。保留样本区间、ATR平滑/均值和零方差规则；A股行情输入口径按 DEC-20/21 使用同花顺。
- `PositionSide` 只表示 LONG/SHORT；策略标签独立为 `StrategyTag`，动作独立为 `ActionKind`。风控使用 `OIStop` / `VolumeStop` 显式表达单位，旧JSON表示只由 `TradingState` 的读写边界编解码，不向策略暴露无单位的混用字段。
- `TradingState` 唯一持有持仓与观察的可变集合；策略取得独立快照，返回 `Decision` / `StatePatch`，不得直接写共享状态。新判断、观察基准变化和无动作更新都经引擎提交。
- `TradeExecutor` 统一 prepare/submit/reconcile/complete_result 协议，并声明真实订单恢复日志需求；BinanceExecutor 调真实 API，AshareExecutor 返回虚拟成交。执行器不写业务状态、不发通知。结果类型区分成交、失败、确认无仓，查询未知不能当成零仓。`prepare_cycle()` 返回市场上下文和状态补丁，启动核对也只能由引擎提交。
- 引擎在准备订单后发交易前信号，收到确认成交后先提交可确定状态/平仓记录，再按需补查实际均价或剩余仓位，最后发交易结果通知。通知异常/取消不撤销已确认状态；未成交/未知结果不伪造成功或增加止盈计数。保留飞书信号在币安下单前、PushPlus在成交后的用户时序。
- 成交后的公共建仓、移除、记录与写入只有一套实现；不同市场的止盈轨道/DCA/冷却由策略返回相应变更，不能用市场名称分支把业务规则塞入引擎。
- 第二阶段必须修改：新单文件所有内部调用方及新入口测试；需要验证：上一阶段全部用户规则与数值/时序对照、状态读取与保存格式、多实例隔离、成交失败/取消/未知订单。仍待调查：实现中的细节接缝，无待用户决定的业务取舍。不修改原入口、不增加额外运行模块、不启动实盘、不自动提交推送。

以下为第一阶段接口历史（第二阶段逐项迁移，禁止保留仅转发的兼容包装）：

- `MarketContext` 携带本批时间、历史范围和是否只允许退出；每批共享的日历请求只属于这一批。
- `fetch_bars(symbol, context)` 返回该市场原有 bars 类型；基类通过泛型约束后续判断使用同一种数据，市场之间无需互转。
- 基类 `process_instrument`：读取本地状态 → 子类本地/冷却前置校验 → 获取一次行情 → 已持仓调用 `manage_position`，未持仓调用 `evaluate_signal` → 将返回的 `OpenSignal` 交给 `execute_action` → 市场观察后处理。子类不另起绕过该流程的扫描入口。
- `evaluate_signal` 可以按既有规则刷新观察基准，返回开仓决策或 None，不直接下单。`manage_position` 判断退出、DCA 和轨道更新，交易动作经同一 `execute_action`；`OpenSignal` / `ClosePosition` / `AddPosition` 明确区分动作载荷。
- `execute_action` 保留真实/虚拟交易的状态提交边界和通知时序：币安飞书在下单前、PushPlus 在下单返回后；AUTOA 在本地建仓后通知。拒单不伪造持仓。
- `build_daily_report` 构建每日报告；`send_market_alert` 实现飞书/企业微信差异，发送日志、PushPlus 与连接生命周期归基类。
- 概率结果计算复用基类，列表与 pandas 样本统计、两种 ATR 算法均保持旧数值口径。

## 整体验收

- 两个策略都是实例，由同一个 `TradingEngine` 编排生命周期和状态提交。
- 公共接口只有一套，市场差异全部落在子类实现边界内。
- AUTOA 收盘涨停池只做新增/刷新；失败、空池、非交易日不破坏已有观察。
- AUTOBN/AUTOA 每日推送后各刷新一次标的池，盘中不重复拉取。
- 缓存按实例隔离，状态 JSON 兼容，旧入口行为对照通过。
- 验证启动补拉失败后的下一分钟不再请求交易对；每 15 分钟不触发账户全量同步；缺记录实际仓位按DEC-23生成可管理的N恢复持仓。
- 验证启动/每日读取实际持仓、拒绝残余仓位上的 OPEN、部分止盈后重启保留剩余状态及计数；真实订单增量恢复日志不改变完整快照频率，AUTOA 写盘失败不阻断虚拟平仓。
- 验证每日四步顺序、失败/取消、节假日、收盘新增/命中/未命中/空池合并，以及每日和扫描之间互斥。
- 新入口测试、回测指标、ruff 和 diff 检查通过。
- 同花顺四类A股数据统一直连，新入口不需要AkShare；来源差异按用户授权试用，交易算法及币安调用链保持。

## 遗留风险

- 新入口与旧入口并行期间不能同时运行，否则会重复调用行情和通知接口。
- 真实外部 API 的限流、网络中断、强制终止和断电恢复仍需按现有边界验证。
- 同花顺免费公开端点没有本次验证可依赖的长期可用性保证；已观察过502，重试失败会跳过该标的。历史复权和完整OHLCV与旧供应商有差异，本次不回填旧持仓阈值。
