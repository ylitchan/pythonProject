# AUTOBN 持仓执行顺序与代码复用

## 目标

修复普通止盈成交后查询剩余仓位失败导致计数及目标价未写回的问题；统一成交后的状态更新，简化多空持仓管理、开仓判断、ATR 计算和 5m 缓存逻辑。

## 现场

- 基线 `dev@988bd45f`，多头止损在所有止盈阶段均只由 OI 触发。
- 已复现普通止盈：30 单位平掉 21 后剩余仓位查询失败，内存持仓记录仍保留旧 `tp_count=1` 和目标 11；下一轮同价又平掉 6.3。
- 当前自动策略按 symbol 维护一个仓位；`rzq_token` 在已有仓位时只执行管理，不另开相反方向。
- 现有 AUTOBN 及调用链测试可作等价性基线；`.codestable/attention.md` 为空，无相关 lesson。
- 另一个工作游标 `issue-autoa-state-flow.md` 正在处理 AUTOA 与共享初始化；保留其文件和修改，当前任务只触及 AUTOBN 及对应测试。

## 边界

- 用户明确暂不处理：请求超时但可能已成交后的重复止盈；不扩展同币同时多空持仓。
- 保留订单异常重试数量与账户按 symbol 的模型，不改变 OI 阈值和退出优先级。
- 保留多头仅 OI 止损、首次及后续部分止盈、空头价格止损/追踪止损和 DCA 触发规则。
- 唯一意图性行为修复：仅在确认成交后更新止盈阶段；剩余仓位查询失败也保存已确认成交对应的新目标与计数。
- 不把止盈衰减移到本轮平仓判断前，不跨加仓/止盈状态变化复用旧盈利或目标距离。
- 不调用真实交易、行情或消息接口，不改业务 JSON/Excel，不自行提交或推送。
